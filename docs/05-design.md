# 05 · Дизайн и визуальный язык

> **🗺️ Ключевые файлы:** `tailwind.config.js` (дизайн-токены), `src/components/*.tsx` (презентационные компоненты), `src/App.tsx` (трёхколоночный layout / `md:` брейкпоинты).

Визуальная метафора — **жёсткое ограничение**, а не украшение.

## Метафора

Экран — это _«Папка с делом, разложенная на столе детектива»_: физические бумажные
документы, официальные бланки, чернильные штампы, архивные папки. Аудитория 30–60, поэтому
UI ставит во главу **высокую читаемость текста, минимализм, чёткую иерархию данных и
крупные зоны нажатия** — а не зрелищность.

**Красные линии — НЕ вводить:** неоновые эффекты, мультяшную графику, игровые/sci-fi
градиенты, фэнтези-элементы, эстетику мобильного казино. Ядро эмоции: _«Я заметил ложь и
разоблачил мошенника»_.

## Токены дизайна

> **Редизайн (палитра «Сепия 1970-х»):** хром стола переведён на палитру поджаренной
> архивной бумаги с терракотовым акцентом (бриф `docs/prompts/from-design/SEPIA-1970-palette.md`).
> Метафора, вёрстка и структура токенов не менялись — только значения цветов; все пары
> текст/фон проверены на WCAG AA+. Прошлые «манильные» хром-токены (`bg #ECE3D2`,
> `accent #2F8F83`) больше не используются.

Заведены в `tailwind.config.js` — **не хардкодь hex**, используй имена:

| Токен | Hex | Назначение |
| ----- | --- | ---------- |
| `bg` | `#E5D7BD` | фон стола (поджаренная архивная бумага) |
| `surface` | `#F1E7D1` | сайдбары / панели (светлая архивная бумага) |
| `surface-2` | `#D7C6A5` | вложенные блоки внутри панелей |
| `border` | `#C5AF87` | границы панелей / блоков |
| `paper` | `#F7EFDD` (manila) / `#F3F4F6` (dossier) | листы документов (CSS-переменная `--paper`) |
| `ink` | `#2A2117` | текст на белой бумаге документа |
| `text-light` | `#3D3119` | основной текст на хроме стола |
| `text-muted` / `text-dim` | `#6B5733` | вторичный / приглушённый текст на хроме |
| `accent` | `#884A28` (manila) | основные действия — тёмная терракота (`--accent`) |
| `success` | `#5C7A33` | Approve (ретро-оливка) |
| `danger` | `#B23A2E` | Reject |
| `gold` | `#C98A2E` | подсветка ежедневного дела — **только заливка/рамка/иконка, не текст** |
| `stamp` | `#A8201C` (manila) / `#DC2626` (dossier) | чернильный штамп «противоречие» (`--stamp`) |

Мобильный стол дополнительно использует именованные токены `mobile-*`, `daily-*`,
`folder-gold-*`, `mobile-solved*`, `mobile-locked*`, а бумажный ID-блок — `photo-*` и
`document-*`. Это точные алиасы прежней мобильной палитры, включая `daily-card`,
`folder-sealed`, `photo-placeholder` и тени `mobile-daily`/`mobile-folder`/`photo-id`;
`modal-backdrop` задаёт затемнение диалогов. Компоненты не содержат inline hex/rgb.
У мобильных карточек базовые `bg-gold`/`bg-surface`/`bg-surface-2` служат непрозрачными
подложками под точные `daily-*`/`folder-gold-*`/`mobile-*` оттенки.

Скроллбар — `#C9B089` (см. `src/index.css`). Тосты остаются тёмными
(`#2B2018` + рамка `stamp`), чтобы читаться поверх стола. Папка манилы: обложка `--folder`
`#CBAA6C`, тёмная вкладка / шапка-баннер бланка `--folder-edge` `#8A6A30` (текст `--paper`).

Шрифты: `font-serif` (IBM Plex Serif) для документов/заголовков, `font-sans` (Inter) для
UI-хрома. Кастомные тени `shadow-folder` / `shadow-lift` дают листам физическую глубину.

## Экран начальной загрузки

`index.html` сразу показывает статический splash до выполнения JavaScript. После
старта React `BootScreen.tsx` подменяет его визуально идентичным `GameLoader` без
пустого кадра. Статическая полоса неопределённая — браузер не сообщает достоверный
процент загрузки module graph; после запуска JS процент строится по реальным сигналам
SDK, сейва, валидации дел и критических ресурсов. Общие стили находятся в
`src/components/GameLoader/GameLoader.css`, фоны — в `public/game-loader/`.

**Splash не содержит текста** — только фон-обложка и карточка статуса с процентом
(language-neutral цифры) и полосой прогресса. Ни заголовка, ни подзаголовка, ни
штампа, ни подписи фазы, ни подсказки: локализовать нечего, поэтому нет ни
дублирующей копии строк в `index.html`, ни pre-JS определения локали, ни риска
рассинхрона языка сплэша с языком игры (его выставляет `App.tsx` после гидратации).
Единственное доступное имя секции для скринридера — процент. Отдельные CSS-правила
покрывают телефон, короткий portrait и низкий landscape.

## Layout

Десктоп — три колонки «следственного стола»:

- **Левый сайдбар** (~272–280px): навигация по делам + прогресс + выбор языка.
- **Центр** (макс ~480px): папка с делом.
- **Правый сайдбар** (~272–280px): бейдж уровня + XP-бар, серия, баланс, точность %,
  кнопка архива ачивок, лидерборд.

Оба сайдбара видны на `md`+ **всегда**, включая онбординг. Раньше они гасились по
`metaUnlocked`, но игра теперь стартует сразу в деле (автостарт в `App.tsx`), и новичок
проходил всю цепочку 1–3 без боковых панелей. Онбординг-гейт остался только у
`MobileDeskMenu` и у кнопки «назад к столу».

На мобильном стол заменяется `MobileDeskMenu` — но только когда он действительно рендерится:
во время онбординга (`metaUnlocked === false`) меню подавлено, поэтому трёхколоночный layout
обязан остаться видимым и на мобильном (иначе новичок получает пустой экран). Признак —
`mobileDeskMenuShown` в `App.tsx`; он же управляет классом `hidden md:flex` у колонок.
Активное расследование становится одной
сфокусированной колонкой: боковые панели скрыты, снизу закреплён verdict action-bar с safe-area,
контент не уходит под него. Улика открывается полноэкранным bottom-sheet со скроллом только тела,
sticky-футером штампа и навигацией «‹ N/M ›». Тема папки задаётся `FOLDER_LOOK`
(`'manila' | 'dossier'`, сейчас `manila`) → класс `theme-*`. Хром-токены (`bg`/`surface`/…)
не зависят от темы — кремовый стол общий для обеих; `theme-*` переключает только цвета
папки/бумаги/штампа (`--folder` / `--paper` / `--accent` / `--stamp`).

## Бюро особых дел

> v3 layout note: коммерческая часть собрана в **один тёмный каркас** (handoff
> `todo/detective-bureau-ui-format-1-v2.zip`). Общая шапка `TopBar` тянется и на стол, и на Бюро;
> внутри Бюро — герой, вкладки Архивы / Штампы / Наборы и бумажные слои поверх ночного фона.
> Токены каркаса: `topbar*` (шапка) и `bureau*` (экраны Бюро) в `tailwind.config.js` — хардкод hex
> по-прежнему запрещён.

`TopBar` — единственная сквозная хрома: бренд-марка «НЛ», **рельс вкладок** с двумя главными
маршрутами, ресурсные чипы (★ XP, ₽ баланс) и шестерёнка (restore purchases).

Навигационный рельс (v3): «Расследование» и «Бюро особых дел» — один утопленный компонент
(`topbar-rail`), а не кнопка рядом с рекламным баннером. У каждой вкладки свой знак (линованная
карточка дела / сургучная печать AR), двухстрочная подпись и hover / pressed / selected. Выбранный
раздел — приподнятая плашка (`topbar-tab-on` → `topbar-tab-on-2`) плюс золотой маркер снизу, без
рамки по периметру. Вкладка Бюро остаётся выбранной на всех его экранах; непросмотренный контент —
медная точка на печати (в accessible name уходит суффиксом `newArchive`).

Ширина вкладок **не фиксируется**: рельс — flex, каждая вкладка занимает ровно ширину своей
подписи (`whitespace-nowrap`, без `truncate`). Эластичен только бренд — он ужимается первым,
поэтому рельс никогда не переполняет шапку.

Схлопывание идёт тремя ступенями. Ниже 1024 px исчезают вторые строки вкладок и тэглайн бренда, а
отступы шапки, вкладок и чипов ужимаются. Ниже 768 px уходят чип XP, шестерёнка и полные подписи
вкладок; **обе вкладки остаются** компактными знаками с однословной подписью
(`navInvestigationShort` / `navBureauShort`), ни один главный маршрут не исчезает. Accessible name
вкладки не зависит от ширины (`aria-label`), состояние — `aria-current="page"`.

Переключение стол ⇄ Бюро — **без exit-анимации и без `AnimatePresence`**. Стол под Бюро
показывается в тот же кадр, когда `bureauOpen` становится `false`; уходящий экран Бюро, доигрывая
fade, продолжал бы держать свою высоту в той же колонке, а потом схлопывался — расследование
прыгало вверх. Появление Бюро по-прежнему с fade-in (`initial`/`animate`).

`SpecialArchivesEntry` — витрина на столе: три обложки архивов веером на тёмной подложке, подпись
«Новое · 1 дело бесплатно», название featured-архива и CTA. В десктопном `RightSidebar` через проп
`archivesSlot`, в `MobileDeskMenu` — в варианте `compact`. Featured-архив = первый некупленный.

`BureauArchives` — полка карточек (обложка + бейдж «1 дело бесплатно» + цена + «Подробнее»,
кликабельна целиком, Enter/Space) и страница архива: большая обложка с сургучной печатью,
плашки «10 новых дел / 30+ улик / 1 особый штамп», эпиграф, пара CTA, блок «В архив входит» и
сетка дел (открытые — бумажные, закрытые — тёмные с замочной скважиной).

`BureauWorkshop` — верстак: слева настоящий бланк с живым оттиском и выбором цвета чернил,
справа каталог подписей. Тап по любой плитке — только выбор (примерка на бланке); единственная
кнопка действия живёт в полосе под бланком рядом с чернилами и меняет глагол по выбранной подписи:
«Используется» (disabled) / «Поставить на печать» / «Купить · цена» (Yandex IAP) / «Открыть набор →»
(уводит на страницу архива, который её содержит).

`BureauBundles` — «Полное собрание»: веер из трёх обложек, зачёркнутая цена, фактический процент
скидки и одна кнопка. Ниже — два меньших блока в той же бумажной рамке: «Три расследования»
(`bundle_archives`) и «Отключение обязательной рекламы» (`noads_forever`, единственная точка
покупки этого права). Чип «Спецпредложение · −N%» появляется только когда оффер реально активен
(`resolvePrice().offerActive`), а цена всегда берётся у того product id, который спишет кнопка.
Каталог показывает три сюжетных пака по 10 дел («СНТ „Ромашка“», «Поезд №13», «Санаторий „Прибой“»); коммерческие
действия доступны, когда payments API отвечает, иначе витрина остаётся browse-only. Системная оболочка остаётся
в метафоре следственного архива, даже если тема пака допускает более необычные материалы внутри.

## Ежедневное дело — премиальный вид

Золотые рамки + штамп «URGENT» на обложке папки, плюс ×2 множитель награды.

## Услуги и развитие отдела

Перед первым открытием улики `CaseFile` показывает лист «Распоряжение на расследование»:
можно выбрать одну доступную услугу отдела или начать без услуги. Выбранная услуга не
подсказывает вердикт напрямую: архив показывает только число противоречий, разрешение даёт
одно дополнительное открытие в бюджетном деле, эксперт раскрывает статус первой выбранной
улики. После первого открытия лист скрывается.

Правая колонка содержит «План отдела» с тремя подразделениями. Карточки оформлены как
официальные бухгалтерские строки: текущий уровень 0–3, следующий эффект и цена улучшения.
Уровень 1 открывает услугу, уровень 2 даёт скидку, уровень 3 — один бесплатный вызов за
серверный день.

## Поток штамповки и анимации

Отклонение требует обоснования (открыть любую улику → «Отметить как противоречие»). Штамп
доступен и на подтверждающих уликах: ошибочная отметка снижает награду. Отклонение с нулём
штампов выводит промпт _«Отклонение должно быть обосновано…»_ вместо сабмита
(см. `handleReject`). Анимации (подъём карточки, выезд документа, демпфер масштаба
чернильного штампа) — на Framer Motion.

Текст оттиска — не константа: бесплатный `classic` печатает ключ `contradiction`, купленные
подписи приходят из `src/data/stampTexts.ts` (`activeStampTextId` в `PlayerStats`). Латинская
подстрока под оттиском в `StampModal` — всегда английский вариант той же подписи.

## Рендереры улик

Каждый тип улики (`EvidenceType`) имеет свой визуальный рендерер, чтобы карточки выглядели
по-разному (GPS-трек, фото с filename, CCTV-запись с моделью камеры, терминальный лог,
рентген, банковская выписка, детализация звонков, соцсеть, документ, протокол свидетеля).
Метаданные рендера — опциональное поле `Evidence.meta` (`EvidenceMeta`); рендереры
фолбэчат на дефолты, поэтому старые дела без `meta` работают. Список meta-полей по типам —
[07-authoring-content.md](07-authoring-content.md) и `CASE_AUTHORING_GUIDE.json`.

Подробный бриф по редизайну карточек улик — `docs/prompts/DESIGN_PROMPT_EVIDENCE_CARDS.md`.

## Компоненты (`src/components/`)

`CaseFile` (папка), `CaseSelect` (выбор дела), `EvidenceCard` (карточка в сетке),
`StampModal` (модалка улики + штамп), `InvestigationServiceOrder` (предварительная услуга),
`DepartmentPlan` (развитие отдела), `VerdictPanel` (кнопки вердикта),
`ResultSheet`
(единый финальный лист: реакция + разбор + награда), `LeftSidebar` / `RightSidebar`, `TopBar`, `SpecialArchivesEntry`,
`BureauScreen` (+ `BureauArchives` / `BureauWorkshop` / `BureauBundles`), `AchievementsModal`,
`RatingModal`, `LanguageSelector`, `Tooltip`, `icons.ts`.

**Мастерская штампов** (вкладка «Штампы» в `BureauScreen`) — косметическая витрина подписей штампа
противоречия. Товар — сам оттиск: он живьём стоит на бланке слева, а каталог справа показывает
превью каждой подписи (некупленные приглушены) с живой ценой из каталога Yandex. Каталог подписей —
`src/data/stampTexts.ts`; длинные подписи ужимают кегль оттиска в `EvidenceCard` и `StampModal`,
чтобы угловая лента и печать не разъезжались.

**Цвет чернил.** `STAMP_INKS` (там же, `stampTexts.ts`) — бесплатные цвета оттиска. Это данные
каталога, а не токен: значение выбирается по runtime-id, поэтому `App.tsx` кладёт его в
CSS-переменную `--stamp-ink` на `<html>`, а три места оттиска (`StampModal`, `EvidenceCard`,
верстак) читают её. Токен `stamp` при этом **не трогается** — он красит и не относящуюся к оттиску
хрому (перерасход бюджета, тосты, зоны аномалий), которая не должна синеть вместе с печатью.

`ResultSheet` — **единственная** модалка финала дела: реакция человека и награда живут на одном
кремовом листе, без промежуточной кнопки «Продолжить». Лист устроен как колонка: одна
прокручиваемая область и закреплённый внизу ряд кнопок (лист длинный — вердикт не должен
превращаться в поиск скроллом). Сверху вниз: **один** штамп исхода (форма + пиктограмма + текст —
никогда не один цвет), портрет-досье 82 px с лёгким наклоном по `emotionalMode` (у режима `grave`
наклон нулевой, портрет приглушён и появляется чуть позже), имя, реплика на карточке стенограммы
с цветной левой линейкой — не в мультяшном облаке (доступна целиком сразу, посимвольной печати
нет), строка Веры. Сразу за репликой — чек: гонорар/убыток крупно, ряд чипов
(XP · мастерство · бонус) вместо плиток и «удвоить награду» под суммой (деньги и рекламный CTA
не должны уезжать за нижний край на телефоне). Ниже — шкала точности и построчный разбор либо
ящик «Что вы упустили», затем ящик «Почему такое решение?», пунктирная карточка «Новая запись
в Архиве №17», повышение и ачивки.

Оба разбора — **сворачиваемые ящики (`Drawer`), закрытые по умолчанию**: строка 44 px с шевроном,
раскрывается и закрывается на месте (никаких новых модалок), заголовок остаётся видимым в
открытом состоянии — иначе открытое нечем закрыть. Состояние отдаётся скринридеру через
`aria-expanded` / `aria-controls`. «Что вы упустили» набран красным цветом отказного штампа —
это разбор ошибки; «Почему такое решение?» держит нейтральный цвет листа. Открытая панель
подтягивается в видимую область (`scrollIntoView({ block: 'nearest' })`): ящики стоят внизу
прокручиваемого листа и иначе раскрывались бы за нижним краем. Лист открывается на исходе и
сумме, а анализ игрок вытягивает сам.

Сюжетные слои (реплика и запись в Архиве) не показываются при неверном вердикте; разбор —
показывается. Раскрытие идёт **одной** лентой на весь лист: штамп 0.1 с → реплика 0.34 с
(`grave` +0.16) → сумма 0.5 с (счётчик стартует вместе с блоком, а не на mount) → шкала и
строки 0.78 с → архив, повышение и ачивки 1.15 с; последняя анимация шкалы затихает к ~1.7 с.

Лист стоит самостоятельно, с тенью и без тёмной внешней рамки; затемнение остаётся только на
полноэкранной подложке.

Кнопки в подвале `ResultSheet` различаются по исходу дела:
* **успех** — `← К столу` (скрывается при `hideBack` во время онбординга) + основная
  `Следующее дело →`;
* **провал** — две равнозначные кнопки в ряд: `↺ Расследовать заново` (перезапускает то же
  дело с чистой сессией) и `Следующее дело →`, плюс тихая ссылка `← К столу` под ними.

Игровой root не допускает выделение текста и отменяет нативное контекстное меню по правому клику:
взаимодействие должно ощущаться как работа с физической папкой, а не как с веб-страницей.

### `Tooltip` — нюанс для тестов

`Tooltip` дублирует подпись в DOM как скрытый `<span role="tooltip">` (чистый CSS-hover).
На мобильном недоступное действие нельзя оставлять `disabled` с hover-only объяснением:
контрол остаётся тапаемым в приглушённом стиле и показывает причину тостом либо имеет видимую
инлайн-причину. Tooltip допускается как дополнительное desktop-объяснение. **Тест-гоча:** когда подпись тултипа
повторяет строку, встречающуюся ещё где-то (напр. `rejectNeedsProof` — и в тултипе, и в
тосте), `findByText` находит два совпадения и падает — фильтруй `{ ignore: '[role="tooltip"]' }`.
## Interactive evidence UI

`InteractiveEvidence.tsx` supplies five reusable, case-ID-independent renderers:
`DocumentScanEvidence`, `ThermalScanEvidence`, `ShadowTimeCheckEvidence`, `SealMatchEvidence` and
`SurfaceRevealEvidence`. Each receives only evidence JSON, persisted progress, locale and a progress
callback. Shared chrome provides reset and three hint levels; the conclusion and contradiction state
stay hidden until `successCondition` is met.

All controls have keyboard-sized hit targets and work with Pointer Events. Surface reveal uses a
128×128 service mask evaluated after each stroke and `touch-action: none`; seal matching supports
drag/rotate; Arabic switches the component and final link board to RTL. Visual assets use `asset()`
and lazy image loading, while thermal overlays, shadow geometry and masks are procedural.

Thermal scan hotspots are not pre-rendered: `heatZones` stay invisible on the grayscaled image until
the player's pointer comes within `THERMAL_SCAN_RADIUS` (percent units, tracked via `onPointerMove` on
the image container), at which point the zone's opacity ramps up by proximity — the player scans the
photo to discover the anomaly rather than clicking an already-glowing marker. A pointer-following ring
(fixed 84×84px, so it stays circular regardless of the 16:10 container) gives scanning feedback even
when no zone is nearby. A compact temperature readout follows at the ring's upper-right edge on an
opaque archive-paper backing: it blends `ambientTemperature` toward the nearest zone's `temperature`
by proximity and shifts from the standard muted brown to red as the pointer approaches heat. The
`observationTime`/elapsed-minutes cells stay below the image since they're needed for the cooling-time
reasoning. Hint level 3 force-reveals all zones (matching the
level-3 highlight convention in `DocumentScanEvidence`); clicking a zone still works before it is
visually revealed so keyboard/screen-reader users (who tab to the button's `aria-label`) aren't
disadvantaged by a mouse-only discovery mechanic.
